## 2. Method

Every step here is **PROPOSED** unless marked otherwise. "AI" means the approved tool from the Ingredients list.

| # | Who | What happens |
|---|---|---|
| 1 | **Human (preparer)** | **Check the project's AI status.** If AI is banned, or it's unclear, skip steps 4–5 and do steps 6–10 entirely by hand, using the same checklist, naming rule, and folders. If it's unclear, treat it as banned until someone confirms. |
| 2 | **Human (preparer)** | **Set up.** Confirm which requirement this is. Open its approved checklist, the naming rule, and the folder template. |
| 3 | **Human (preparer)** | **Gather the files into one working spot.** Narratives, calculators, and proof are made the same way they are today. (**CONFIRMED** that these are prepared today. **UNKNOWN** who prepares them and where they're stored.) |
| 4 | **AI** | **Suggest, but don't change anything.** For each file, the AI suggests (a) which checklist category it fits, (b) a filename that follows the naming rule, and (c) a folder location. It works only inside the approved tool. |
| 5 | **AI** | **Flag what it isn't sure about.** The AI flags (a) files it can't confidently categorize, (b) files that look like duplicates or older versions, (c) files that may not belong to this requirement, and (d) checklist items with no matching file, labeled "possibly missing." **The flags are hints, not decisions.** |
| | **Handoff 1** | The AI gives the preparer a list of suggestions and flags. No files have been renamed or moved yet. |
| 6 | **Human (preparer)** | **REVIEW POINT 1: review every suggestion.** Accept, edit, or reject each one. Sort every flagged file by hand. |
| 7 | **Human (preparer)** | **Apply only approved changes.** Renames and moves happen only for suggestions the human approved. Keep a record of the original filenames so any change can be undone. |
| 8 | **Human (preparer)** | **Organization check.** Make sure every file is in the right folder with the right name, and note which checklist items still have no file. This checks organization only. It does **not** decide whether the evidence is good enough. |
| | **Handoff 2** | The preparer sends the organized set to the qualified reviewer. (Who receives it: **ASSUMPTION TO CONFIRM**) |
| 9 | **Human (qualified reviewer)** | **REVIEW POINT 2: evidence decision.** Decide whether the documents are accurate and sufficient evidence for the requirement. **AI plays no part in this decision.** If the answer is no, the set goes back to the preparer with what's needed (**PROPOSED**; what happens today is **UNKNOWN**). |
| 10 | **Human** | **Into the package.** The approved set goes into the design package for upload and USGBC review. (**CONFIRMED** that a design package is uploaded and reviewed. How one requirement's files are added, and who uploads them: **UNKNOWN**) |

### Confidentiality rules for this recipe (PROPOSED)

- **Client documents stay inside an approved tool.** They never go into a personal or unapproved AI tool.
- **Banned projects follow the manual path in step 1.** Using AI on them would break the signed form (**CONFIRMED** that the form exists).
- **Our team works only with approved or sanitized samples.** Any testing happens under the NDA (**CONFIRMED** that an NDA is required).

## 4. Chef's Note

**The one responsibility AI must never take over:** deciding whether the documents are accurate and sufficient evidence that the building meets the certification requirement.

**Why this has to be a qualified human**

- **Organizing is not judging.** An AI can notice that a file *looks like* proof. It can't tell whether that proof actually shows this building meets this requirement. That takes knowledge of LEED and of the specific project.
- **It matches how ecoPreserve already works.** Oscar said AI is "an enhancer, not a replacer," and that the firm doesn't hand off recommendations "based on real experience" to AI. (**CONFIRMED**)
- **Someone has to be accountable.** ecoPreserve submits these packages on the client's behalf, and a person needs to stand behind that.

**What could go wrong if AI made this decision.** These are possible risks, not things that have happened.

- **The wrong file gets accepted.** It could be an old draft, the wrong version, or a file from a different building, approved because its name or format looked right.
- **A missing or weak document gets called "complete."** The AI matched something to the checklist even though the evidence doesn't really prove the requirement.
- **Calculator mistakes slip through.** Organizing a calculator file doesn't check whether its numbers are right.
- **Reviewer pushback and delays.** USGBC reviewers already send questions and comments back (**CONFIRMED**). Weak evidence could mean more rework. How much: **UNKNOWN**.
- **Trust is damaged.** A false claim of compliance could hurt the client's certification and ecoPreserve's reputation.

**Other things AI also shouldn't do in this recipe:** choose credits, write the strategy narrative, or fill in calculators. Those stay with staff, the same as today.
